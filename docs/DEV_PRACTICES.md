# 开发实践经验总结

本文档用于记录项目开发过程中实际遇到的问题、调试经验和好的实现方式。

后续每次开发功能模块时，如果遇到值得复用的实现方式、踩坑点或架构微调，应补充到本文档。

## 当前实践约定

- 开发功能前先阅读 `docs/ARCHITECTURE.md`。
- 架构相关变化写入 `docs/ARCHITECTURE.md`。
- 具体 coding 经验、调试问题、实现技巧写入本文档。
- 不把临时实现经验散落在对话或代码注释里，除非它能帮助理解当前代码。

## 已沉淀经验

### 1. 模拟数据也要按真实接口结构组织

即使第一阶段使用模拟数据，也应按照未来真实系统的资源结构组织，例如基金、走势、持仓、行业暴露、研报和 AI 结论分别暴露接口。

这样后续替换数据源时，可以优先改后台数据适配，不需要大面积重写前端页面。

### 2. 实时数据和季度持仓必须明确区分

基金走势可以分钟级刷新，但持仓数据通常来自季报，存在披露滞后。

开发展示逻辑时，不要暗示季度持仓等同于当前实时持仓。后续页面上也应该明确展示持仓季度、披露日期和数据来源。

### 3. AI 结论需要保留证据链

AI 趋势结论不能只是单独一句判断，应尽量包含：

- 输入数据范围
- 关键持仓或行业暴露
- 相关研报观点
- 置信度或不确定性说明
- 后续观察指标

这样用户更容易判断结论是否可信，后续也方便做审计和回溯。

### 4. 前端图表优先保持轻量

早期原型可以使用原生 Canvas 绘制趋势图，减少依赖和工程复杂度。

当后续需要更多交互能力，例如缩放、十字光标、指标叠加、同类基金对比时，再引入专业图表库会更合适。

### 5. 页面展示不承担复杂分析

前端负责展示和交互，复杂的指标计算、行业聚合、AI 结论生成应放到后台。

这可以避免同一套逻辑在多个页面重复实现，也方便后续增加定时任务和缓存。

### 6. 服务入口要保持薄

服务入口只负责启动服务和组合路由。模拟数据、分析计算、接口路由、静态文件服务应拆到独立模块里。

这样后续接入真实数据源、数据库或后台任务时，不需要在一个大文件里拆逻辑，维护成本更低。

### 7. 自选和预警先走 API

即使第一阶段使用内存状态，自选基金和预警也先通过 API 暴露。

这样前端交互方式会更接近正式系统，后续替换成用户账户、数据库持久化和规则引擎时改动更小。

### 8. 接口响应可以提前携带解释字段

预警响应除了标题和正文，还应返回触发条件。AI 结论除了摘要，还应返回数据范围和证据来源。

这些字段能帮助用户理解系统为什么得出结论，也方便后续做审计、回放和调试。

### 9. 本地服务默认监听本机地址

本地开发环境里，Node 服务监听默认地址可能触发权限限制。服务入口默认使用 `127.0.0.1`，需要调整时再通过 `HOST` 环境变量覆盖。

### 10. 路由处理函数要明确返回已处理状态

API 路由写入响应后，要返回明确的已处理状态。否则服务入口可能继续走静态资源处理，造成重复写响应头错误。

### 11. Git 初始化可能需要在本机终端执行

当前开发会话可能阻止创建 `.git` 目录。遇到这种情况时，可以先维护 `.gitignore`，再由用户在本机终端执行 `git init`、首次提交和远程推送。

### 12. 排名和调仓变化由服务层计算

同类基金排名、综合评分、季度持仓变化这类结果应在服务层生成，前端只负责展示。

这样后续替换为真实行情、季报解析和更复杂的评分模型时，不需要同步改多个页面。

### 13. 本地数据库文件不进 Git

SQLite 文件属于运行时数据，应放在 `data/` 下并通过 `.gitignore` 忽略。仓库只提交 schema、Provider、初始化脚本和种子数据。

这样既能让项目开箱可跑，又不会把本地状态、用户自选或未来真实数据提交到远程仓库。

### 14. 种子数据只负责初始化

`src/data/mockData.mjs` 现在是种子数据，不再是业务服务的直接数据源。服务层统一通过 Provider 读取数据。

这能让后续接真实数据源、数据库迁移、后台任务时少改业务逻辑。

### 15. 外部数据先同步入库，再由业务接口读取

真实基金数据接入时，不让前端直接请求第三方接口。先由 `src/dataSources/` 适配器拉取数据，再通过同步脚本写入 SQLite。

这样可以控制调用频率、保留数据快照，也能在第三方接口不可用时继续展示已有数据。

### 16. 真实数据和模拟回退要并存

历史净值同步成功后，趋势接口优先使用 `fund_nav_history`；没有同步数据时继续回退到模拟曲线。

这个回退机制能让开发环境开箱可跑，也避免外部接口异常直接打断页面。

### 17. 新导入基金要支持缺失数据空状态

从外部搜索导入的基金通常先只有基础信息和历史净值，季报持仓、行业标签、研报可能暂时缺失。

服务层和前端都要把这视为正常状态：持仓、持仓变化、行业暴露、研报和 AI 结论应返回可解释的空状态，而不是抛错。

### 18. 同步状态要可见

真实数据接入后，页面必须显示数据来源、记录数和最新净值日。用户需要能判断走势图是来自真实净值历史，还是因为未同步而使用模拟回退。

同步状态由服务层从 `fund_nav_history` 和 `sync_runs` 计算，前端只展示结果。
